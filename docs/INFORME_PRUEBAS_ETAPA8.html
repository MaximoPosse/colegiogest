Criterios y evidencia utilizada

COLEGIOGEST

Qué se revisó

  • Los requerimientos de Etapa 2 y los registros de implementación/pruebas disponibles en el repositorio.
  • El código actual de vistas, servicios, componentes, router, migraciones SQL, políticas RLS y documentación.
  • La aplicación en navegador con cuentas de demostración para acceso por rol y dos filtros.
  • El catálogo remoto de Supabase en modo de solo lectura, después de aplicar las migraciones 009 y 010.
  • Instalación limpia en una copia temporal con npm ci y compilación de producción.

Qué no se hizo

  • No se crearon, editaron ni eliminaron registros escolares durante esta revisión.
  • No se midieron tiempos de rendimiento, compatibilidad en cuatro navegadores ni accesibilidad con Lighthouse/axe.
  • No se probaron envíos reales de correo, copias/restauraciones ni los rechazos del hardening con escrituras en producción.

Cómo interpretar estados

Implementado: la funcionalidad existe en la versión actual. Las pruebas específicas pueden seguir pendientes.
Parcial / verificar: hay una limitación o falta una prueba operativa/medición.
Pendiente: no se dispone de evidencia suficiente para declarar cumplimiento.
V2: requerimiento explícitamente planificado para una versión futura; no se considera defecto de V1.

Las pruebas PI/UI antiguas se citan como evidencia histórica de `docs/PRUEBAS_ETAPA6.md`; no se presentan como ejecutadas de nuevo. Las pruebas UI12–UI15 se realizaron en la revisión del 15/11/2026.

Estado del entorno remoto

Proyecto Supabase Colegiogest en producción. Las migraciones 001–010 aparecen sincronizadas. La migración 009 endurece perfiles, bajas y fechas; la 010 habilita el alta directa de administradores.

Criterio de seguridad: que la función o política exista y se haya inspeccionado no sustituye la prueba de comportamiento que demuestre el rechazo. No se realizaron pruebas destructivas en producción.

La aplicación presenta menús por rol, etiquetas en formularios, estados de carga, mensajes en español y confirmaciones en operaciones destructivas. Se comprobaron rutas y pantallas principales con cuentas de demostración; no se realizó un estudio formal con usuarios.

Responsive

El CSS incorpora ajustes para móvil y el manual incluye capturas móviles. El viewport usado en las capturas no acredita específicamente el ancho mínimo de 360 px ni todos los flujos en tablet/escritorio. Marcar como pendiente hasta completar esa matriz.

Accesibilidad

Se observan etiquetas y nombres accesibles en controles principales. No se ejecutó auditoría Lighthouse/axe ni recorrido completo solo con teclado/lector; no se declara WCAG AA cumplido.

Rendimiento

Compatibilidad

Hay evidencia en Chromium. No se documentó una matriz para Chrome, Firefox, Edge y Safari.

Relaciones, índices, políticas, funciones y triggers están presentes. No se realizó una restauración de backup ni se verificó el plan de respaldo del proyecto.

Repetición de pruebas

Las migraciones 009 y 010 están desplegadas y registradas; se verificaron de solo lectura políticas, funciones, aridad y permisos. No se ejecutaron altas/escrituras académicas en producción. El retest recomendado debe hacerse en una base aislada con datos sintéticos:

  1. Usuario intenta cambiar su propio nombre/DNI/correo/rol/estado: todas las escrituras deben rechazarse.
  2. Admin desactiva profesor con asignación vigente: se bloquea; sin asignaciones: puede continuar.
  3. Alta sin contraseña o con menos de seis caracteres: falla; contraseña válida: alta autorizada.
  4. Asistencia/nota de mañana por UI y API: rechazo; fecha actual/pasada válida.
  5. Repetir login, RLS, CRUD e integración para asegurar que no hubo regresión.

Organización y calidad

La estructura separa vistas, componentes reutilizables, servicios de Supabase, mapeadores, router y stores. Se corrigió un tipo de prop de icono en `StatCard.vue`; `npm run build` pasó. No se ejecutó un análisis estático exhaustivo ni se hicieron refactors adicionales.

Estado final de la versión

COLEGIOGEST

ColegioGest dispone de los módulos principales para gestión escolar, trabajo docente y consulta de alumnos. La base, las migraciones 001–010 y RLS están instaladas; los flujos históricos de integración y las pruebas de UI documentadas aportan evidencia útil.

Comprobado con evidencia

  • Build de producción aprobado.
  • Login/logout de los tres roles y guardas de rutas.
  • Pruebas históricas de asistencia, calificaciones, asignaciones, actividades, avisos y aislamiento entre alumnos.
  • Filtro de avisos por fecha, búsqueda de alumno en asistencia y formulario de alta de administrador con validación vacía.
  • Migraciones 009–010 aplicadas; permisos y funciones principales inspeccionados tras el despliegue.

Pendiente para declarar validación completa

  • CRUD manual completo con datos de prueba.
  • Retest de denegaciones y fechas futuras tras hardening.
  • Mediciones RNF05, matriz de navegadores, responsive 360 px y auditoría de accesibilidad.
  • Prueba real de correo de recuperación y backup/restore.
Conclusión: implementación funcional y compilable, con evidencia histórica aprobada y hardening de seguridad desplegado. La versión no debe describirse como completamente validada hasta ejecutar los casos pendientes en un entorno aislado y registrar sus resultados.
